# Asteroids — language ports

Asteroids ships in seven implementations, all driven by the same Frame state
machine and selectable from the version drop-down on the game page:

| Version | Source | Build |
|---|---|---|
| JavaScript (Phaser) | `games/asteroids/src/` | bundled by Vite |
| Godot · GDScript | `games/asteroids/godot/` (+ `games/asteroids/frame/`) | `npm run build:godot` |
| Godot · C | `build/spike-c/` | `npm run build:godot-c` |
| Godot · Rust | `build/spike-rust/` | `npm run build:godot-rust` |
| Godot · C++ | `build/spike-cpp/` | `npm run build:godot-cpp` |
| Flame · Dart | `build/spike-flame/` | `npm run build:flame` |
| raylib · C | `build/spike-raylib/` | `npm run build:raylib` |

The three GDExtension ports (C / Rust / C++) live under `build/spike-*/`. Those
directories are **gitignored except their source** — the Frame/host/godot-project
files are tracked; everything generated or downloaded is not:

- **C** — `asteroids.fc` (Frame), `gameplay.c` (raw GDExtension C host),
  `gdextension_interface.h`, `godot/` project. Ignored: generated `asteroids.c`,
  `godot/bin`, `godot/out`, `godot/.godot`.
- **C++** — `asteroids.fcpp`, `main.cpp`, `register_types.cpp`,
  `gdextension_interface.h`, `godot/` project. Ignored: generated
  `asteroids.cpp`, the `godot-cpp-45/` clone, build outputs.
- **Rust** — `rust/asteroids.frs` (Frame), `rust/src/gameplay.rs` + `lib.rs`
  (hand-written gdext host), `rust/Cargo.{toml,lock}`, `rust/.cargo/config.toml`,
  `godot/` project. `rust/src/asteroids.rs` is the framec-generated FSM (tracked
  so a clone builds without framec, but regenerated by the build script).
  Ignored: `rust/target/`, `node_modules/`.

The **Flame** port (`build/spike-flame/`) is a Flutter app, not a Godot project:
`asteroids.fdart` (Frame), `app/lib/main.dart` (the hand-written Flame host),
`app/pubspec.{yaml,lock}`, `app/web/`. `app/lib/asteroids.dart` is the
framec-generated FSM, regenerated by the build script. Ignored: `app/.dart_tool/`,
`app/build/`. It needs **framec 4.6.1+** — earlier dart codegen had no public
constructor (framec #108), so a separate host file couldn't instantiate the FSM.

The **raylib** port (`build/spike-raylib/`) reuses the **Godot-C Frame source
verbatim** (`build/spike-c/asteroids.fc`) — the C FSM is engine-agnostic (its own
`Vector2` + a `ShipHost` struct of function pointers), so Godot-C and raylib
differ only in the host. Tracked: `raylib_host.c` (the raylib/emscripten host) and
`shell.html` (the canvas shell — fixed 800×600 framebuffer, `object-fit:contain`
letterbox). Ignored: the cloned `raylib/` checkout (built for web on first run),
the generated `asteroids.c`, and the emcc outputs. The whole bundle is ~324 KB
(150 KB wasm) — the smallest of any port. raylib's default font is ASCII-only, so
this port's hint text uses ASCII tokens (`|`) rather than the glyphs (`·`/↻/⚡/⏸)
the others use.

## Shared engine

A Godot web export is ~46 MB, ~99% of it the engine. All four Godot ports use
the **same** dlink engine (exported with `extensions_support=true`), so it's
hoisted to one `games/asteroids/versions/_engine/` and each game dir is just its
`.pck` + extension `.wasm` + a thin loader pointing `executable` at
`../_engine/`. `build/share-engine.sh` performs the split; the build scripts call
it. The browser caches the engine once, so switching language tabs is instant.

The **Flame** port doesn't share anything — a Flutter web app bundles its own
CanvasKit runtime (~37 MB of the 39 MB bundle), served self-hosted
(`--no-web-resources-cdn`) so it's fully self-contained.

## Reproducibility — what a clean clone still needs

The deployable bundles are committed, so the **site runs from a clone**. To
*rebuild* the ports, run **`bash build/bootstrap.sh`** — it installs/builds the
auto-installable toolchain (emsdk 4.0.20, Rust nightly + rust-src, and godot-cpp
at `godot-4.5-stable` built arm64 + web) and reports what you must supply by hand
(`bash build/bootstrap.sh --check` reports without installing). The pieces:

- **Godot 4.6.2** on `PATH` (or `GODOT=`) + the Web export templates.
- **framec** (`FRAMEC=`) — for C++, needs the no-exceptions codegen (issue #86).
- **emsdk 4.0.20** sourced (`~/emsdk/emsdk_env.sh`) — must match Godot's emscripten.
- **Rust nightly + rust-src** (for `cargo -Zbuild-std`), and `GDRUST_GODOT_BIN=`.
- **godot-cpp at `godot-4.5-stable`** (master segfaults on 4.6.2; 4.5 is
  forward-compatible), prebuilt for arm64 + web (`threads=no`,
  `disable_exceptions=yes` for the web lib) at `build/spike-cpp/godot-cpp-45/`.
- **Flutter 3.44.x** on `PATH` (or `FLUTTER=`), web enabled — for the Flame
  port. Unlike the Godot ports it's CI-buildable, so the deploy workflow
  rebuilds it on every push (`subosito/flutter-action` + `npm run build:flame`).
- **emsdk 4.0.20** (same as the Godot C/C++ ports) for the **raylib** port;
  `build/raylib.sh` clones + builds raylib 5.5 for web on first run. Committed
  bundle (like the other emscripten ports), not CI-rebuilt.

Known follow-ups:
- A **toolchain bootstrap** (clone+build godot-cpp 4.5, fetch templates, etc.) so
  the ports rebuild from a clean checkout. Partly automated by `bootstrap.sh`.
- Each GDExtension export leaves the headless Godot process in macOS **UE**
  (uninterruptible) state — a 4.6.2 editor doc-gen cleanup bug. The bundle is
  written first, so builds are correct; the zombies clear only on reboot. The
  build scripts `disown` rather than `wait` on them.
- **framec dart polish:** the dart backend doesn't emit a suppression header
  (the rust target emits `#[allow(...)]`), so the generated FSM trips ~900
  analyzer warnings. `build/flame.sh` prepends an `// ignore_for_file:` line as
  a stopgap; the backend should emit it itself.

## Roadmap — candidate ports

Every port is gated by two things: the language must be a **framec target** and
have a **web-deployable engine/runtime**. framec already targets far more than
we've built (`python_3, typescript, javascript, rust, c, cpp, java, kotlin,
swift, ruby, csharp, go, php, dart, gdscript, lua, erlang`), so the engine side
is usually the gate. Each new *backend* is also fresh framec bug-finding surface
(the Dart port surfaced framec #108).

Built so far: JS (Phaser), Godot · GDScript/C/C++/Rust, Flame · Dart, raylib · C.

| Tier | Language · Engine | framec target | CI-buildable | Notes |
|---|---|---|---|---|
| **Next up** | Go · **Ebitengine** | `go` | yes | first-class `GOOS=js` WASM, small, clean — the standout. (Blocked on framec #112: Go backend emits cross-system calls with the wrong case.) |
| | Lua · **Defold** | `lua` | yes | tidy HTML5 export (or LÖVE/love.js, or Fengari minimalist) |
| **Workable** | C# · **Unity** | `csharp` | **no** | $0 (Personal), but proprietary editor + license-in-CI → committed-bundle only; Brotli-on-Pages gotcha |
| | Python · **Pygame/Pygbag** | `python_3` | yes | high "Python in the browser" appeal; heavy Pyodide runtime, slow cold start |
| | Kotlin · **KorGE** | `kotlin` | yes | Kotlin/JS or /Wasm multiplatform engine |
| | Java · **libGDX (TeaVM)** | `java` | yes | big language, older-feeling web toolchain |
| **Stunt** (no real engine → hand-roll a canvas renderer over JS/WASM interop) | Swift · SwiftWasm · Ruby · ruby.wasm · PHP · php-wasm · Erlang · AtomVM | `swift` `ruby` `php` `erlang` | varies | maximal "Frame runs *anywhere*" novelty; Erlang is the only *functional* target |

Priorities: **Go/Ebiten**, **Lua/Defold**, and **C/raylib** are the cleanest
(CI-buildable, each exercises an untested framec backend). **Python/Pygbag**
earns a slot on appeal despite the weight. **Unity** is worth doing for C#-target
coverage but as a manual local build (see the cost notes). The stunt tier is for
a "look, even this" flourish once the practical ports are in.
